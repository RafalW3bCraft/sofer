# sofer — Technical Spec

## How This Works, In Plain Language

sofer has two halves.

The **frontend** is a single-page web app: a React + TypeScript + Vite application that runs in the learner\'s browser. It holds five screens (Home, Lesson List, Lesson Player, Alphabet, Progress). It loads curated lesson content (the five MSA beginner sentences with full per-token annotations) from a static JSON file at build time. It reads and writes the learner\'s progress to the browser\'s localStorage under a single versioned key. When the learner taps "Explain with AI tutor," the frontend makes a small, schema-validated HTTP request to the backend\'s `/api/ai/explain` endpoint.

The **backend** is a tiny Node + Express server. Its only job is to act as a secure gateway between the learner\'s browser and a Token Factory API (Nebius Token Factory by default — see `External Services and Dependencies`). The backend holds the `TOKENFACTORY_API_KEY` so the key never reaches the browser, validates the request shape, calls Token Factory, validates the response shape, and returns a structured payload to the frontend. When Token Factory is unavailable or returns an unexpected response, the backend returns a structured 503 and the frontend shows the curated fallback.

Both halves are deployed from the same repository. For local development the frontend runs on Vite\'s dev server (port 5173) and the backend runs on port 3001, with Vite proxying `/api/*` to the backend. For a production preview, the frontend is built into static assets and the backend serves them. The submission is verified to run via `npm install && npm run dev` and via `npm run build && npm start`.

This shape was chosen because the kernel — tap a token, see a real curated explanation — needs no server identity, no database, and no account. The backend exists only because the AI tutor needs a place to keep the provider key out of the browser bundle. That is the entire reason the backend exists.
## The Core Journey Through the System

The PRD\'s Core Journey, traced step by step through the pieces above. PRD ref: `prd.md > The Core Journey`.

1. Learner visits the URL → Vite dev server (dev) or Express static handler (preview) returns `index.html` and the React bundle.
2. React mounts, reads `sofer.progress.v1` from localStorage. If absent or invalid, the app starts fresh. Routes: `/`, `/lessons`, `/lessons/:id`, `/alphabet`, `/progress`.
3. Learner clicks **Start Learning** → `/lessons` → renders the lesson list, which is derived from the static `lessons.json` plus the localStorage progress (lesson `completedAt` populates the checkmark).
4. Learner opens `/lessons/greetings-1` → the lesson player renders the Arabic sentence, the per-token tap targets, and the comprehension question.
5. Learner taps a token → a local state transition opens the token panel. **No network call.** The panel content comes from the static lesson data.
6. Learner picks a comprehension answer → local state transition reveals feedback derived from the curated correct/incorrect explanations. **No network call.** A single `progress.v1` write happens: `{ [lessonId]: { completedAt, lastQuestionCorrect } }`, plus the running totals `totalQuestionsAnswered` and `totalQuestionsCorrect`, plus `lastActivityAt`.
7. Learner taps **Explain with AI tutor** → `POST /api/ai/explain` with `{ context, arabic, lessonId, tokenIndex? }`. Backend validates with Zod. Backend calls Token Factory. Backend validates the response with Zod. Backend returns `{ explanation, model, generatedAt, cached }` on success, or `{ error, reason }` on failure. Frontend renders `explanation` as plain text with a "Generated by AI" badge. On failure, frontend renders the curated fallback with an "AI tutor unavailable" status pill.
8. Learner closes the tab, returns tomorrow → localStorage is still there. The lesson list shows completion. `Next lesson` resumes correctly.

## Stack

Frontend
- React 18, TypeScript (strict mode), Vite 5.
- React Router 6 for client-side routing.
- Zod for runtime validation of API responses.
- Vanilla CSS modules (no Tailwind, no Radix). System font stacks. CSS variables for the warm-neutral palette.
- `window.speechSynthesis` for pronunciation. No external audio assets.

Backend
- Node.js 20 LTS, Express 4, TypeScript.
- `tsx` for dev, `esbuild` for build (consistent with the OmniLanguageTutor pattern; sized down to two files).
- Zod for request and response validation.
- `node-fetch` not required — Node 20 has global `fetch`.
- No ORM. No database driver. No auth library.

Testing
- Vitest for unit and integration tests.
- Playwright for one browser end-to-end test (full lesson flow).
- A small in-process mock Token Factory server (`tests/mock-tokenfactory.ts`) that listens on a configurable port and records requests.

Rationale per learner-selected choice
- React + TypeScript + Vite: learner is comfortable with this stack, and it\'s the smallest modern setup that supports static deployment.
- Express (not a serverless function or Fastify): one narrowly scoped POST endpoint, easy to reason about, easy to mock.
- Vanilla CSS modules (not Tailwind): the warm-neutral minimalist aesthetic is easier to author in plain CSS, and removing Tailwind drops ~30 MB from the build.
- Vitest + Playwright (not Jest + Cypress): faster, smaller, and the OmniLanguageTutor audit showed no existing tests, so the new project gets a clean baseline.

Anything unverified
- **Token Factory model selection.** ~~Not yet retrieved~~ — resolved during `5-build`: a live `GET /models` against Nebius Token Factory (2026-10-23) returned 29 models; `TOKENFACTORY_MODEL` defaults to the verified `Qwen/Qwen3-235B-A22B-Instruct-2507`. See `docs/release/live-smoke.md`.
- **Arabic speech voice availability** is browser- and OS-dependent; the spec handles this with the "Listen button hidden when no Arabic voice" fallback described in `prd.md > Features and Behavior`.

## Where It Runs and How Someone Tries It

Runtime: browser (frontend) + local Node process (backend). No external hosting required for the POC.

Environment requirements
- Node.js 20 LTS or newer.
- One optional environment variable: `TOKENFACTORY_API_KEY`. The application runs fully without it; the AI tutor endpoint serves the curated fallback.
- Optional `TOKENFACTORY_BASE_URL` (defaults to the documented Token Factory base URL once verified in `4-spec`).
- Optional `TOKENFACTORY_MODEL` (default placeholder; resolved against the provider\'s model list).
- Optional `TOKENFACTORY_TIMEOUT_MS` (default 15000).

Exact start commands
- Local dev: `npm install`, then `npm run dev`. Opens `http://localhost:5173`. Vite proxies `/api/*` to `http://localhost:3001`.
- Local production preview: `npm install`, `npm run build`, `npm start`. Opens `http://localhost:3001`.
- Tests: `npm run test` (Vitest unit + integration), `npm run test:e2e` (Playwright browser test). Requires Playwright browsers installed once via `npx playwright install chromium`.

Required demo recording: the demo script in `devpost/demo-script.md` walks through `npm run dev` → Home → Start Learning → first lesson → tap a word → answer comprehension question → Progress screen → tap "Explain with AI tutor" with `TOKENFACTORY_API_KEY` set, then again with it unset. Total runtime under three minutes.

Deployment is optional. The README documents a static-host path (e.g. GitHub Pages for the frontend, Fly.io or Railway for the backend) but the POC submission does not publish.

## Components

### Home
What it does: shows the wordmark, one-sentence framing, and the **Start Learning** button. Talks to nothing.
PRD ref: `prd.md > Screens and Layout` (Home).

### Header
Persistent across all routes. Wordmark on the left, three links (**Learn · Alphabet · Progress**) on the right. On mobile, links collapse into a "Menu" disclosure that uses native `<details>` / `<summary>` (no JS) for keyboard-friendliness.
PRD ref: same.

### LessonList
Reads static `lessons.json` + localStorage progress. Renders a vertical list with completion checks.
PRD ref: `prd.md > Features and Behavior > Lesson content`.

### LessonPlayer
Three regions: SentenceArea (Arabic + translation + transliteration toggle + token targets), QuestionArea (MCQ with feedback), NavigationFooter (Back / Next).
PRD ref: `prd.md > Features and Behavior > Token inspection` and `> Comprehension check`.

### TokenPanel
Inline below the sentence on small screens, side panel on desktop. Receives the tapped or focused token via lifted state in `LessonPlayer`. Renders Arabic, transliteration, contextual meaning, part of speech, grammar note, optional "Listen" button, and a "Mark as tricky" toggle. Keyboard accessible: Escape closes and returns focus to the originating token.
PRD ref: `prd.md > Features and Behavior > Token inspection`, `prd.md > Interactive behaviors`.

### AiTutorButton
A button on tokens and on the whole sentence. On click, fires `useAiExplain` which calls `/api/ai/explain`. Renders the explanation in a labeled panel ("Generated by AI · Model X · Just now"). On failure, renders the curated fallback with an "AI tutor unavailable" pill.
PRD ref: `prd.md > Features and Behavior > AI tutor (optional)`.

### AlphabetGrid
28-letter grid on `/alphabet`. Each cell: letter, name, isolated form, "Listen" button. Below the grid: a short section on الحركات (short vowels).
PRD ref: `prd.md > Screens and Layout` (Alphabet intro).

### ProgressPanel
Reads localStorage, derives counts and accuracy, renders summary, "Reset progress" button with confirmation.
PRD ref: `prd.md > Features and Behavior > Progress tracking`.

### Server endpoint `POST /api/ai/explain`
Request: `{ context: "word" | "sentence", arabic: string, lessonId: string, tokenIndex?: number, requestId: string }`.
Validation: Zod schema. `arabic` ≤ 500 chars. `requestId` UUID v4.
Behavior: builds a tight prompt with the lesson context; calls Token Factory with `TOKENFACTORY_MODEL`, `TOKENFACTORY_TIMEOUT_MS`; validates the response with a Zod schema; returns `{ explanation, model, generatedAt, cached: false }` on success or `{ error, reason: "provider_unavailable" | "schema_mismatch" | "rate_limited" | "timeout" | "invalid_request" }` on failure. All errors are 5xx with structured payloads; never a 200 with a fabricated explanation.
PRD ref: `prd.md > Features and Behavior > AI tutor (optional)`.
## Data Model

### Lesson data (static, build-time)
File: `client/src/content/lessons.json`. Schema (Zod-validated at build time):
```
Lesson = {
  id: string,
  topic: "greetings" | "numbers" | "directions" | "food" | "shopping",
  title: string,
  objective: string,
  difficulty: "A1",
  sentences: Sentence[]   // length 2–3 per lesson; total across all lessons = 7
}
Sentence = {
  id: string,
  arabic: string,        // with full diacritics
  english: string,
  transliteration?: string,
  tokens: Token[],
  question: Question
}
Token = {
  start: number,         // UTF-16 code-unit offset into arabic
  end: number,
  arabic: string,        // exact substring; never a normalized or stripped form
  transliteration: string,
  meaning: string,       // contextual, in this sentence
  partOfSpeech: "noun" | "verb" | "adj" | "prep" | "pron" | "particle" | "interjection" | "punct" | "other",
  grammarNote: string
}
Question = {
  prompt: string,
  options: [string, string, string, string],
  correctIndex: 0 | 1 | 2 | 3,
  correctExplanation: string,
  incorrectExplanations: [string, string, string]  // one per incorrect option
}
```

Validation: a small `scripts/validate-lessons.ts` script runs Zod over the JSON and fails the build if anything is malformed (offsets out of range, mismatched correct index count, etc.).

### Progress data (runtime, localStorage)
Key: `sofer.progress.v1`. Schema:
```
ProgressV1 = {
  schemaVersion: 1,
  lessons: { [lessonId: string]: { completedAt: string, lastQuestionCorrect: boolean } },
  totalQuestionsAnswered: number,
  totalQuestionsCorrect: number,
  lastActivityAt: string
}
```

### Tricky tokens data (runtime, localStorage)
Key: `sofer.tokens.v1`. Schema:
```
TrickyTokensV1 = {
  schemaVersion: 1,
  tricky: { [tokenId: string]: { markedAt: string } }
}
```
Token ids are stable and equal to `<lessonId>:<sentenceId>:<tokenIndex>` so a token can be looked up by lesson+sentence+index without re-deriving from offsets.
On read: if the JSON is missing, malformed, or `schemaVersion` is unsupported, the app starts fresh and shows a one-time inline notice "Your progress was reset." No crash.

On reset: clears the key entirely.

### Alphabet data (static, build-time)
File: `client/src/content/alphabet.json`. Same Zod-validated pattern: 28 letters with `id`, `name`, `isolated`, `transliteration`, `audioHint?` (no audio asset; the speech synthesizer handles it).

## External Services and Dependencies

### Token Factory provider (Nebius by default; AMD is a different provider)
Endpoint: `POST {TOKENFACTORY_BASE_URL}/chat/completions`, with `GET {TOKENFACTORY_BASE_URL}/models` for discovery. Auth: `Authorization: Bearer $TOKEN...EY`. Body: OpenAI-compatible chat completions payload, with parameters known to be supported by the chosen model.

Two providers expose this shape. **They are different companies, accounts, and keys — not regions of one service.** A key from one returns 401 at the other (verified 2026-10-23).

- **Nebius Token Factory** — `https://api.tokenfactory.nebius.com/v1`. The verified live hackathon credential is a Nebius key; this is the server default. Live-smoked 2026-10-23 (`GET /models` 200, 29 models; `POST /chat/completions` 200 with `Qwen/Qwen3-235B-A22B-Instruct-2507`). Evidence: `docs/release/live-smoke.md`.
- **AMD Radeon Cloud Token Factory** — `https://developer.amd.com.cn/radeon/api/v1` (China site). Docs: https://amd-aim.github.io/radeon-cloud-docs/guides/token-factory/ and https://amd-aim.github.io/radeon-cloud-docs/api/chat-completions/. Requires its own AMD-issued key. **Not live-tested** — the Nebius hackathon key returns 401 there.

Limits enforced by the server
- `TOKENFACTORY_TIMEOUT_MS` (default 15000) — abort via `AbortController`.
- Per-IP rate limit on `/api/ai/explain`: 30 req/min, sliding window, in-memory. (Not persisted; reset on restart. Sufficient for a POC; documented limitation.)
- Global concurrency limit: 4 simultaneous outbound provider requests. Excess requests get a 429 with `reason: "rate_limited"` and a `Retry-After: 5` header.
- Request body size cap: 8 KB.
- Output length cap: 800 chars in the validated response schema; longer outputs are rejected with `reason: "schema_mismatch"`.

Failure modes the server handles
- 401 / 403 from provider → 503 `provider_unavailable` (do not leak credential info).
- 429 from provider → 503 `rate_limited` with `Retry-After` propagated.
- 5xx from provider → 503 `provider_unavailable` with bounded retry (1 retry, exponential backoff with jitter, respect `Retry-After`).
- Timeout → 503 `timeout`.
- Schema mismatch → 503 `schema_mismatch`. Logged with a short request id (no payload contents).
- Unknown model → 503 `provider_unavailable` with the message "Model not available."

### Backend dependencies

## Important Failure Modes

- **No `TOKENFACTORY_API_KEY` set.** → Backend returns 503 `provider_unavailable` on the very first request. Frontend renders the curated fallback explanation with the "AI tutor unavailable" status pill. Lessons and progress are unaffected.
- **`TOKENFACTORY_API_KEY` set but provider unreachable.** Same path as above. The "AI tutor unavailable" message is the same; nothing is fabricated.
- **Corrupted localStorage.** → `lib/storage.ts` returns `null`, the app starts fresh, and the Progress screen shows a one-time inline notice "Your progress was reset."
- **No Arabic voice available in the browser.** → "Listen" buttons are hidden. The lesson still works. No silent failure.
- **`NODE_ENV=production` without `npm run build`.** → `npm start` errors out cleanly with a message about the missing `dist/` directory.
- **Browser does not support `window.speechSynthesis`.** → "Listen" buttons are hidden across the app.

## What Was Simplified and Why

- **No account system** instead of a full multi-device progress sync — the kernel does not need identity; a guest POC has zero value-add from auth. The full version would add a small accounts service + cloud progress storage.
- **Seven sentences in the MVP** instead of a CEFR-aligned curriculum — proves the kernel end to end without spending the entire hackathon on content authoring. The full version would extend to 50+ sentences across more topics with audio.
- **A single `/api/ai/explain` endpoint** instead of a multi-route AI tutor surface — the kernel only needs one explanation-on-tap path. The full version would add free-form Q&A, follow-up questions, and example-sentence generation, each behind its own narrowly scoped route.
- **Plain CSS instead of Tailwind** — the warm-neutral minimalist aesthetic is easier to author in plain CSS, and removing Tailwind drops ~30 MB from the build. The full version would not gain from reintroducing Tailwind.
- **In-memory rate limiting** instead of a Redis-backed limiter — sufficient for a POC; the limit is documented and the trade-off is explicit. The full version would back this with a persistent store.
- **No production deployment** — the submission runs locally via `npm run dev` or `npm run preview`. The README documents the static-host path so a reviewer can deploy if they choose. The full version would automate the deployment.

## Decisions and Open Issues

Decisions
- **Stack: React + TypeScript + Vite + Express + Zod + Vitest + Playwright.** Tradeoff: small, well-understood, fast to ship, easy to review. Cost: hand-rolled accessibility and rate limiting.
- **AI provider: Token Factory via Nebius endpoint by default** (the provider the authorized hackathon key actually belongs to). The AMD Radeon Cloud endpoint is configurable via `TOKENFACTORY_BASE_URL` but is a separate provider with its own keys and was not live-tested. Tradeoff: a single point of failure for live integration; mitigated by the curated fallback.
- **No production deployment.** Tradeoff: the submission is verified locally, not over the public internet. Acceptable for a Devpost POC.
- **Vanilla CSS over Tailwind.** Tradeoff: more lines of CSS, smaller bundle, less dependency surface.

Genuine learner uncertainty
- ~~**Token Factory model selection.**~~ Resolved post-spec during `5-build`: live `GET /models` against Nebius Token Factory returned 29 models (2026-10-23); `TOKENFACTORY_MODEL` defaults to the verified `Qwen/Qwen3-235B-A22B-Instruct-2507`. See `docs/release/live-smoke.md`.

Open issues
- **Alphabet content depth.** How many letter forms to include (isolated / initial / medial / final). Default in this spec: isolated only. Final decision can be deferred to alphabet page implementation in `5-build`.
- **Transliteration scheme.** Default: simplified learner-friendly. Final decision can be deferred to lesson content authoring.
- **Whether to commit a non-empty `.env.example`.** Yes — it will contain only variable names and example placeholders, never real credentials.
